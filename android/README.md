# TavernAgent Mobile（Android 原生客户端）

TavernAgent Web 应用的移动端入口：连上你自己的（本机或局域网）TavernAgent 服务后，在手机上继续故事。
客户端**只负责交互与展示**；剧情推演、记忆、状态、选项与能力判定全部以服务端为准，本地不做任何业务推断。

- 技术栈：Kotlin 2.3 / Jetpack Compose（Material 3）/ OkHttp + kotlinx.serialization / DataStore / Coil
- `minSdk 26`、`targetSdk 36`、`compileSdk 36`；单 `:app` 模块；无 DI 框架（`AppContainer` 手写装配）
- 与后端的关系：只走 HTTP REST + SSE，不改动任何现有后端与 Web 代码

---

## 1. 构建与运行

前置：JDK 17+（本仓库验证于 JDK 21）、Android SDK（platform 36 / build-tools 36）。`local.properties` 指向 SDK：

```properties
sdk.dir=C\:\\Users\\<you>\\AppData\\Local\\Android\\Sdk
```

```bash
cd android
./gradlew :app:assembleDebug          # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest      # JVM 单元/契约测试
./gradlew :app:assembleDebug --offline   # 依赖已缓存时可离线构建
```

在设备/模拟器上安装：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### 连接自己的服务端

1. 在电脑上启动后端。默认只绑定回环，**手机访问必须显式监听局域网地址**：

   ```bash
   go run ./cmd/tavernagent -provider mock -addr 0.0.0.0:8890 -data ./data
   ```

   服务端启动时会打印 6 位配对码（`-pin` 留空即自动生成）。启用 HTTPS：追加 `-tls auto`。
2. 手机与电脑处于同一局域网，在应用首页填写 `电脑IP:8890`（或 `https://电脑IP:8890`），按提示输入配对码。
3. HTTPS 自签证书采用 **TOFU（首次使用即信任）**：应用会展示 SHA-256 指纹让你确认；证书变更会再次要求确认。

> 模拟器访问宿主机用 `10.0.2.2:8890`（等价于宿主机回环，通常无需配对码）。

体验与系统要求：

### 信息架构（聊天软件形态）

底部三个入口：**聊天** · **角色** · **设置**。

- **聊天**：对话列表。每行是一个角色（头像 + 角色名 + 最近一条消息摘要 + 相对时间），
  摘要按会话惰性拉取（`limit=1` 的视图）并按 `updatedAt` 缓存；右上角刷新、右下角「新对话」去挑角色；
  长按/更多菜单可删除对话（服务端 `DELETE /api/v1/sessions/{id}`，永久删除需确认）。
- **角色**：可对话的角色。支持搜索（名字/身份/短名）、导入 PNG / JSON / charx、每行显示「N 段对话」；
  点进去是**角色资料页**：头像/名字/身份/标签、`开始新对话`、与这个角色的历史对话（点按继续）、
  人设 / 性格 / 场景 / 开场白（只读，全部来自服务端卡预览）。
- **聊天页**：沿用原有叙事流设计，只把入口语义对齐聊天——顶栏是**角色头像 + 角色名**
 （点按进入角色资料），副标题是会话名/分支；每条消息头显示相对时间；正文与思考过程支持自由长按划词选中复制；
  菜单保留分支与回溯、角色与状态、记忆库、导演模式、模型设置。
  输入栏胶囊栏包含「主线模型快速选择 / 思考强度调节 / 注记 / 选项呈现模式 / 剧情选项卡」；
  **玩家消息发送成功即回显**（不必等整轮生成），提交后由服务端节点接管、只渲染一次。
- **设置**：分组卡片（发丝描边、无阴影）——**连接**（状态点 + 主机名 + 断开重配）、**外观**（跟随系统 /
  浅色 / 深色分段选择）、**模型与备份**、**朗读**（自动朗读开关、语速 / 音调、后端音色、试听）、**插画**、**关于**（版本）。
- **底栏**：自定义三段式（聊天 / 角色 / 设置）——一条极细分隔线 + 选中药丸 + 主色/次级色区分，
  60dp 高度、无阴影；进入聊天页等二级页面时自动隐藏。

### 排障：只有思考、没有回答

推理模型（DeepSeek / Gemini Thinking 等）的思考增量走直通通道，**思考也消耗输出预算**。
若模型连接的「输出上限」为空，服务端只预留 2048 token，思考很容易吃满预算：上游返回
`incomplete(max_output_tokens)`，本轮以「输出上限截断」收尾，于是界面只见思考不见回答。

- 处理：到 **设置 → 模型设置 → 编辑连接**，把「输出上限」调到 **8192 以上**（新建连接默认即为 8192）。
- 聊天页在被截断时会给出说明条：可点「续写」继续，或去模型设置调大输出上限。

- ✅ 视觉沿用 Web 令牌（颜色、圆角、间距、字体族、叙事排版；明暗双主题，可跟随系统 / 强制浅色 / 强制深色）
- ✅ 生成期间前台服务保活（切后台/锁屏继续接收流），完成/失败发系统通知（Android 13+ 运行时权限）
- ✅ 弱网自动恢复：SSE 退避重连（1/2/4/8/16s，最多 5 次；4xx 不重试）、3s 轮询对账、快照补齐只允许文本变长
- ✅ 重进应用接着上次：记住上次会话，并用 `branch.activeTurnId` + `GET /turns/{id}` 恢复在途回合

### 卡内图片（立绘 / 插画）加载策略

服务端的 `assets[]` 是 `name → URL` 清单，而标记里的键既可能是名字、也可能是被清洗过的引用名（ref），
两者常常不同名（如 `하세가와 아키라_평상복_neutral` ↔ `_____________Neutral.webp`），因此客户端按以下规则解析：

- **解析顺序**（与 Web 端 `resolveCardAsset` 对齐并扩展）：精确 → 忽略大小写 → 去图片扩展名 → 数字后缀变体
  （`anis_casual_surprised` ↔ `anis_casual_surprised3.webp`）→ 资源 URL 末段 ref；名字与 ref 都做 Unicode NFC 归一化。
- **不猜 URL**：资源表尚未到达时按「加载中」处理（500ms 宽限期后才提示失败/缺失），
  绝不按裸键拼 `/assets/{键}` —— 那种请求必然 404，也是此前「图片慢 / 不显示」的根因之一。
- **状态可自愈**：解析结果以资源表为 remember 键，资源表到达即自动重解析；
  加载失败可点按重试（换缓存键重发），缺失资源显示键名提示。
- **缓存**：资源表按「服务器 + cardId」在进程内缓存（重开故事零请求）；图片走 Coil 内存 + 磁盘缓存
  （256MB，`respectCacheHeaders(false)`，服务端返回 `immutable`）。

## 3. 与 Web 端的差异

- **布局**：Web 三栏工作台（脉络 / 阅读 / 立绘舞台）在手机上收敛为单列聊天流 + 顶栏入口；分支、角色、记忆、导演各自独立页面。未实现左/右栏抽屉与平板双栏（竖屏优先）。
- **角色与对话的组织**：Web 以「会话/剧情」为中心，移动端以「角色/聊天」为中心——聊天列表按角色名与最近消息摘要呈现，角色资料页承担继续或新开对话的入口。
- **立绘舞台**：未实现 Web 的立绘舞台（表情切换器、溶墨蒙版）；场景信息以提示行 + 正文内联图片呈现。
- **候选项版本**：未实现"版本 i/n 左右切换"组件；同一父节点的候选通过分支树查看与分叉。
- **编辑回合**：未实现"编辑玩家输入 / 编辑助手正文"（`/edits`）；重生成、分叉、回溯已实现。Web 的"重演"引导以重生成对话框承载。
- **世界书面板**：未实现 `/lorebook` 浏览（接口已在契约文档中记录，留待后续）。
- **朗读**：默认使用系统 TTS（离线可用）；Web 使用浏览器 TTS 或后端音色。后端音色选择与试听在设置页。
- **模型密钥**：模型连接的密钥只存服务端；客户端仅显示"已存密钥"。TTS/生图自定义凭据在 Web 端存 localStorage，本客户端暂未保存（避免明文密钥落盘），仅透传服务端已配置的能力。
- **纯净编年模式**：未实现（Web 的阅读模式），当前为单一沉浸式叙事流。
- **视觉细节**：卡片化叙事 + 发丝线 + 分层 surface 与 Web 一致；但排版的像素级（行高 1.78、字距）按 Android 字体度量做了近似。

### 语义对齐（不做本地推断）

- 可写性以服务端 `capabilities`（`busy / canSend / canFork / viewingHistory / block`）为准；本地只维护瞬时相位。
- 回合相位机与 Web 一致：`idle → generating → truncated → awaiting_confirm → committed → idle`，`generating/truncated/awaiting_confirm/committed` 都视为忙碌。
- 幂等：发送 / 重生成 / 记忆修订等写操作都带幂等键；"结果未知"的重试复用同一键，"明确 4xx（含 429 QUEUE_FULL）"后换新键。
- 思考与草稿是内存态，断线后以服务端 `turn.draft` 快照为准且只允许变长；终态事件后客户端主动断开（服务端不会主动关闭 SSE）。

## 4. 需要后端配合的未决问题

1. **局域网监听的开箱体验**：默认 `-addr 127.0.0.1:8890` 只能本机访问，手机连接必须手动改为 `0.0.0.0`。是否提供"局域网模式"一键开关，或在启动日志中更醒目地打印可访问地址？
2. **配对的免手输**：目前配对码 6 位需人工输入。是否支持二维码 / 深链（如 `tavernagent://pair?host=192.168.1.5:8890&pin=123456`），供客户端扫码直连？
3. **DTO 稳定性**：客户端已对未知字段宽容（`ignoreUnknownKeys`），但 `SessionView.state`、`TurnContent.checks/changes/injectedMemories` 目前按不透明 JSON 处理（仅状态投影做类型化）。若这些结构会长期演进，建议在契约文档中标注为"稳定子集"。
4. **卡库头像 URL**：卡库列表的 `avatar` 可能是 `embeded://…` 等归档内引用。客户端按 `assets/{ref}` 猜测 URL，遇到非标准引用会回退为占位图标。是否在 `GET /api/v1/cards` 的条目里直接给出可访问的 `avatarUrl`？
5. **TTS / 生图凭据**：客户端当前不落盘密钥（与 Web 的 localStorage 行为不同）。若希望移动端直接使用自定义引擎，建议后端保存凭据并由 `/tts/plan`、`/images/plan` 返回"当前可用配置"。
6. **通知深链**：服务端可在事件里带上会话/分支（已有 `branchId`），客户端可据此在通知点击时直达对应故事；需要确认跨进程恢复时以 `sessionId + branchId + activeTurnId` 为准（当前通知只打开应用首页）。
7. **`/api/v1/memories/organize` 返回结构**：客户端按 `{operations, usage, skipped}` 宽松解析，建议在契约文档中固定该形状与错误码。
8. **历史窗口**：视图默认 100 回合、向上翻页按 `before` 游标；长会话缺少"跳到分支头附近"的定位辅助（可用 `headNodeId` 实现，属客户端后续优化）。

### 已做的实机冒烟（Android 35 模拟器 + mock provider）

连接（`10.0.2.2`）→ 书架列表/刷新 → 角色卡库列表 → 打开故事（开场白渲染）→ 输入并发送回合（`POST /turns` 202）→ 轮询对账 → 提交后重载（正文 + 选项 + 思考块）→ 无崩溃日志。
这次冒烟同时抓出一个真实缺陷并已修复：**未启用配对码的连接路径没有持久化地址**，导致进入书架后请求使用空地址。

第二轮（真实数据，PC 端 `0.0.0.0:8890`）：
手机（真机）书架 → 打开三个不同卡片的会话 → 服务端日志确认图片请求全部命中正确 ref
（韩文卡 `_____________Neutral.webp`、Anis 卡 `anis_casual_surprised3.webp`），**零 404**；
清空应用图片缓存后重开同一会话，日志只出现正确 ref 的 `200`，二次打开不再产生任何资源请求（资源表 + 图片双缓存生效）。

第三轮（聊天化重构，模拟器 + 真实数据）：
聊天列表显示角色名 + 真实消息摘要 + 相对时间（服务端日志可见每会话一次 `limit=1` 的摘要拉取，且按 `updatedAt` 缓存）；
角色库显示「N 段对话」并可搜索；角色资料页正确渲染人设与开场白变体；
从资料页「开始新对话」弹窗（对话名称 / 称呼 / 身份 / 开场白）→ 进入聊天页；
聊天页顶栏为角色名 + 会话名副标题，消息头显示相对时间。

第四轮（底栏与设置页打磨）：
底栏改为自定义三段式（细分割线 + 药丸选中态，无阴影，聊天页内隐藏），FAB 与底栏无重叠；
设置页改为分组卡片（连接 / 外观 / 模型与备份 / 朗读 / 插画 / 关于），主题改为分段选择；
顺带修掉一个真缺陷：设置页的连接状态此前**永远显示「未连接」**
（`baseUrl` 的写入被放在永不返回的 `collect` 之后），现已改为实时跟随凭据流。
